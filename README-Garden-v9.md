# Garden 09 · 控雨修正与雨养花

## 固定主题

微笑时屏幕下雨，大笑时屏幕炸开烟花，烟花粒子与头部碰撞后改变方向。控雨与雨养花只增强这三项主体验，不改变表情触发规则。

## 修正原因与实现

1. **旧雨场会回拉。** 原实现把雨滴追向接管前的坐标，减速和松手都可能回弹。改为增量位移：保留雨滴当前位置，按手掌本帧位移和景深权重移动；松手只恢复重力方向的下落，没有回到原位的弹簧。
2. **旧水珠切换突兀。** 雨线长度、透明度和水珠高光随控制强度连续过渡，不再在固定阈值突然替换。
3. **旧开花与雨无关。** 删除按入场时间自动开放的规则。微笑持续时雨量逐渐增加；真实落雨积累花朵含水量，雨滴穿过花朵范围时追加局部水量和轻微触水反馈。悬停时暂停积水，恢复落雨后继续。
4. **开花按枝条顺序。** 初始只有小花苞，先下方，再主花，再上方。六阶段花苞/花瓣图集渐变与大小变化组合，保留脸部中央清晰。开花完成后保留，不因收回笑容突然消失。
5. **输入映射与稳定性。** 人脸和手掌共用同一套镜像、object-fit:cover坐标映射。手掌去抖按实际时间计算；拒绝延迟超过350ms的旧结果，布局变化后丢弃旧坐标，摄像头帧停止时不重复识别旧画面。持续超时会释放控雨，保留表情玩法。
6. **不冻结烟花。** 控雨只调整雨滴；烟花原本的扫掠碰撞、反弹及寿命照常运行。

## 22秒预览节奏

| 阶段 | 可观察结果 |
| --- | --- |
| 0–5.2秒 | 模拟微笑，细雨渐密；低处花苞先开始开放 |
| 5.2–9秒 | 模拟张掌、移动；水珠减速悬停并随手掌分层位移，停止浇灌 |
| 9–16.5秒 | 模拟松手恢复落雨；雨渐密，花朵继续沿枝条开放 |
| 16.5–20.3秒 | 模拟大笑；烟花爆发，头部附近粒子反弹 |
| 20.3–22秒 | 停止新触发，残留粒子收尾，已开的花保留 |

摄像头模式由真人输入控制，以上时间轴只用于明确标注的模拟预览。

## 验证

- `test-cinematic.cjs`：原烟花、头部扫掠碰撞和固定粒子池。
- `test-garden.mjs`：纵向画面、移动头部、先举手再微笑、控雨期间烟花仍碰撞、无人脸清理、无落雨不自动开花。
- `test-rain-control.mjs`：张掌/闭掌、去抖、丢手释放、悬停寿命、上下左右移动和松手落雨。
- `test-action-contract.mjs`：三个画面比例的镜像映射、减速不倒退、松手不回拉、重新接管不瞬移、30/60/120Hz一致性、雨量渐增、枝条开放顺序、暂停浇灌。
- 用Google官方示例的真实手掌照片构造平移及遮挡帧，在浏览器运行HandLandmarker，验证识别→去抖→镜像映射→雨场→丢手释放。另以Canvas视频流经过实际HandInput进行集成测试，详见交付测试记录。
- 设置中新增当前设备的预览FPS与帧处理P95诊断；数值为实际运行读数，不是对所有设备的性能承诺。

数值回归结果：30Hz与120Hz的垂直悬停位移差0像素、水平牵引差约0.30像素。该结果验证数值积分连续性，不代替真人动作和视觉验收。

## 仍然明确的边界

动作样本由一张真实手掌照片合成运动帧，不是真人连续摄像头录像。不能据此声称已覆盖侧掌、遮挡、所有肤色、弱光、低端手机或多人情况。肩侧植物仍由头部位置推算，没有加入肩部追踪；头部碰撞仍为二维代理。真实设备还需要按这些场景验收。
